# Release checklist — 2026-11-10

Target source PC: `192.168.1.4` (`host` Git remote)
Target live site: `fryxo`
Approved Text.lk Sender ID: `LUUV FRYXO`

This release includes the customer menu/item-detail/cart redesign, Android
WebView safe-area and debug URL fixes, Purchase Bill item-category selection,
Kurunegala menu-description data changes, and one-time customer verification
through Text.lk SMS.

The API token is deliberately not in this repository. Enter it interactively
on the live backend as described below.

## 1. Activate the reviewed branch on the 1.4 PC

The development PC pushes this release to the branch named `claude`. That
branch already includes the 1.4 PC's current `main`, so `main` can be advanced
without another merge commit. On the 1.4 PC:

```bash
git switch main
git status --short
git merge --ff-only claude
git log -1 --oneline
```

Do not merge or start a live deploy from a dirty checkout. If `--ff-only`
refuses, stop: `main` changed after this release was prepared and the new state
must be reviewed before deployment.

## 2. Safe code deploy from the 1.4 PC

Follow the repository's guarded VPS workflow. It must have a fresh off-host
backup and a passed rehearsal for this exact app tree:

```bash
deploy/vps-deploy.sh preflight
deploy/vps-deploy.sh backup

export DB_ROOT_PASSWORD='<MARIADB_ROOT_PASSWORD>'
RUN_TESTS=1 TEST_MODULE='luuvcrm.tests.test_customer_auth luuvcrm.tests.test_settings' \
  deploy/vps-deploy.sh rehearse
unset DB_ROOT_PASSWORD

deploy/vps-deploy.sh deploy
deploy/vps-deploy.sh post
```

Do not use `FORCE=1`. If a migrate or smoke check fails, stop and use the
rollback command printed by the deploy script.

## 3. Apply the Kurunegala menu data update

After the code deploy passes, execute the commands and verification in:

[`HOST_DB_UPDATE_2026-11-10.md`](HOST_DB_UPDATE_2026-11-10.md)

from the active Add-ons menu. It does not delete the Item or order history.


[`TEXTLK_SMS_HOST_SETUP.md`](TEXTLK_SMS_HOST_SETUP.md)

Enter the API token only at the hidden terminal prompt. Never paste it into a
Markdown file, Git commit, deployment log, group chat, or screenshot.

## 5. Production smoke checks

1. Open `https://luuvgrand.com/cus?r=Kurunegala` and verify the menu, item
   detail, add-ons, quantity control, cart totals, and checkout sheet.
2. Register a phone number that has no Customer Account. Confirm the SMS comes
   from `LUUV FRYXO`, verify the code, and set a PIN.
3. Sign out and sign in again. The existing account must ask only for its PIN,
   never another OTP.
4. In Purchases → Add bill → Create new item, confirm a category must be chosen
   and that no Entry type / expense category selector is shown.
5. Confirm `clothing` still renders normally; the deploy script's smoke test
   checks this second site as well.
